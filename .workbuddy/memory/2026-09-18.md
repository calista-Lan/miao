## v0.6 需求系统（Lan 说 ok 后开工做完）
按诊断补上了第 1 + 2 层。

**做法**
- `state.needs = { satiety, energy, mood }`，0-100，按真实秒衰减
  （饱食 30min／精力 25min／心情 45min 从满到空），速率在 `NEED_RATE`，参数在 `CONFIG.needs`
- 离线结算：`saveGame()` 写 `lastSeen`，启动时 `applyOfflineDecay()` 补算，上限 6 小时
- `state.want`：饿 > 闷 > 精力过剩，猫会主动冒 🍖 / ? / ✨ 并叫 —— 这是第一条"猫发起 → 玩家响应"
- 尾巴新增 `needy` 姿态（索求时尾尖大幅扫动），`TAIL_TEXT.needy` 同步
- 代价：饱食 ≥85 投喂被拒（白喂一次）；精力 <25 扑不动逗猫棒；心情 <30 摸头收益减半
- 饿着投喂好感 +5（平时 +4）；饱食 >92 触发 `stuffed` 25 秒（接下来更易累）
- 精力 <25 会很快犯困（`sleepNext` 被提前）
- UI：画布下方三条需求条，低于 32 变红闪烁

**踩到的坑**
- 初始精力设 82 时一开场就触发"精力过剩"，猫一直在扫尾巴 —— 开场应该放松。
  已把初始值降到 74、阈值提到 82
- 用 Edit 改 `saveGame` 时 old_string 多吞了一行函数头，导致语法错乱，已修回

**验证**（`.workbuddy/tools/render-verify.js` 新增用例，全过、0 报错）
- 离线 10min → 90/90/90 变 57/50/68（与衰减速率吻合）

- 精力 10 逗猫棒 → 精力不变（被拒）；饿时 `want=food` 且 `tailMode=needy`
- 需求条 DOM 输出 90%/50%/90%

## v0.7 居家场景（Lan 要求"改整体画面，要居家感"）
原画面是"一块天空 + 一块地板"，像在户外；改成**一间屋子**。

**画布内（miao.js）**
- 新增 `ROOM` 调色板：每个颜色都是 `[白天, 夜晚]` 两色，`col(name)` 按 `dayMix` 插值取色。
  **改房间配色只动这一张表**。夜晚刻意选暖棕（室内开灯），不是原先的冷蓝
- `dayMix`（0=白天 / 1=夜晚）在 `updateRoomMix(dt)` 里缓动逼近，`update()` 每帧调用 →
  昼夜切换有 ~1 秒过渡；启动时 `dayMix = settings.night ? 1 : 0` 避免开局闪一下
- 房间分层（`drawRoom`）：`paintWall` 墙＋墙纸竖纹＋灯光衰减 → `drawWallDecor`（顶角线／挂画／搁板）
  → `drawWindow`（玻璃里的天空／太阳云／月亮星星／窗框窗棂／窗台／窗帘）→ `drawFloor`（踢脚线／木地板／地毯）
  → `drawFurniture`（左侧盆栽／右侧猫窝）
- **窗户接管了昼夜**：星星只在玻璃区生成（`STARS` 限制在 616-776 / 68-252），月亮挪进窗格里
- 夜里 `paintGlow` 做自上而下的灯光衰减（`GLOW_BANDS`），地板另叠一层暖光

**关键约束（改房间务必遵守）**
- `eraseWall(x,y,w,h)` 取代了旧的 `eraseSky` —— 生气时飞机耳要擦掉直立耳再重画，
  擦除区必须"还原成墙面"。所以 **`paintWall` 里画了什么（墙纸＋灯光），`eraseWall` 就自动带上**，
  新增墙面效果时务必写进 `paintWall`，否则擦除后会缺一块
- 擦除区是猫头范围 `x 218-582 / y 102-200`，**左边界 582 之内不能再放墙上装饰**
  （挂画右边缘因此定在 208，窗台左边缘定在 594）
- 猫会占满 `x 232-568`（生气后退时到 ~624），墙上和地面的装饰只能放在这个范围之外
- 木地板的板缝／木纹必须用固定算式，**不能用随机数**，否则每帧抖动

**页面（mao.css）**
- 整页从"深色工具风"改成暖居家：白天奶油底＋深棕字，夜晚暖褐底＋暖白字
- 新增变量 `--track`（进度条底）、`--frame`／`--frame-line`／`--shadow`（画布木框）
- canvas 用多层 `box-shadow` 做成挂墙木框（9px 木色 + 内外描边）
- 状态色／尾巴色全部按"浅色背景也看得清"重调；JS 里 `setNeed` 和 `updateUI` 的进度条色同步改为暖色系

**页面截图查出来的坑（值得记住）**
- 之前一直没做过整页截图，这次用 Edge 无头截图才发现：**`.container` 是 column flex，
  canvas 的 `height: auto` 会被 flex 压扁**（页面内容超高时画布高度被压缩，画面变形）。
  修法是给 canvas 加 `flex: none`。这个 bug 从早期就存在，只是没截图看不到
- 逗猫棒按钮的 emoji `🪶`（U+1FAB6）在本机字体里**缺字形**，显示成方框，已换成 `🎣`。
  以后往 UI 加 emoji 要挑老编码的
- Edge 无头截图可用（之前 Chrome 被拦，其实是我把路径写成了 "Microsoft Edge" 带空格，
  真实路径是 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`）。
  命令：`--headless=new --disable-gpu --no-sandbox --user-data-dir=<可写目录> --screenshot=... --window-size=900,1180`

## v0.8 猫变小 + 自主走动（Lan：猫太大了，而且要是猫能自己走就好了）

**一、猫缩小**
- `const S` 由 14 改成 10（猫宽 336 → 240px）。引入 `const K = S / 14`，
  所有"固定 px"的量（胡须粗细、呼吸幅度、粒子出生点、影子半径、迈步深浅）一律乘 K
- 几何改成从常量推导，不再手写：`CAT_FOOT_Y = 452`（脚踩地板）、`CAT_TOP_Y = CAT_FOOT_Y - GH * S`、
  `CAT_HALF_W = GW / 2 * S`；猫的水平中心统一走 `catX()`（= `state.cx + state.bodyOffset`）
- `headCenter()`、`hitTest()`、`FISH_TARGET_Y`、全部 `spawn*` 坐标都改成基于上面这些推导

**二、自主走动（`updateRoam`）**
- `state.cx` = 猫在屋里的身体中心 x；`CONFIG.roam` 存范围（214~648）、速度（56px/s）、停留时长、`spots`（猫窝/窗边/盆栽旁/地毯/中间）
- `canRoam()` 决定什么时候**不许动**：睡着 / 被摸 / 非 relaxed / 在吃鱼 / 逗猫棒亮着 / 跳跃中
- `pickSpot()` 挑去处：别老去同一个地方；**精力低于 `tired+14` 就往猫窝走**
- 走路表现：`stepBob` 身体起伏、`walkPhase` 驱动**两只前爪交替往前探一格**（脚底下面还空着一格地板，
  所以不需要擦除任何东西）、`lean` + `headTurn` 给方向感、每走 52px 脚下扬一点灰
- 尾巴新增 `walk` 姿态；实测走动时间占比约 1/3，会轮流去 3~4 个地方
- `drawNest()` 改成**画在猫之后**：猫走到窝里时下半身被窝口挡住 = "卧进去"

**三、顺手修掉的一个隐藏 bug：耳朵不再"擦墙重画"**
- 原来生气时是 `eraseWall` 把猫头那块墙重画一遍再画飞机耳。猫一旦会走动，这东西就会
  **擦掉挂画和窗户**（擦除区会横移到 x 604+ 撞上窗户）
- 改成：`SOLID_NO_EAR` 把耳朵排除在身体之外，直立耳用 `drawEarsUpright()` 画在身体**之前**
  （耳根被身体盖住，接缝干净），飞机耳用 `drawEarsFlat()` 画在身体**之后**。`eraseWall` 已彻底删除
- 中途试过"两只耳朵都用三角形光栅化"，形状比原像素耳朵差很多（变宽变胖），
  最后是**直立耳沿用 SPRITE 原像素、只有飞机耳才旋转**才对

**踩到的坑（重要）**
- **同一文件的多个 Edit 不能并行发**：工具是"读-改-写回"，并行时后写的覆盖先写的，
  而且每条都回报 Successfully。这次因此丢了 4 处改动（S 常量、胡须、两条尾巴文案、resetGame），
  是靠渲染工装报 `K is not defined` 才发现的。以后要么串行，要么用一段脚本一次改完
